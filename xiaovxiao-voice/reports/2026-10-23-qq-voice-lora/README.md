# 聊天语音整理与 VoxCPM2 LoRA 实验

用户授权从指定 QQ 导出目录提取语音，只训练已确认的聊天对方，与已选定真人 A 音色衔接。质量优先；A 参考克隆仍为已接受基线，实验训练不会覆盖它。

## 当前进度

- 682 条目标发送者语音全部能读取，无缺失、无文件级重复；合计 125.248 分钟，24 kHz 单声道。
- 原始导出保持只读，所有训练数据、转写与权重保存在 E 盘本机 `voices/human-a-v1/local/qq-corpus-20261023/`，不上传聊天内容、原声或训练权重。
- 通过 FSMN-VAD 切出 799 个语音段，保留内部停顿；721 段完成 Paraformer 和 SenseVoice 双转写，均无运行错误，207 段文本完全一致。
- 情绪识别仅为机器候选标签，未当作人工精标；文字分歧、混声和明显噪声进入复核队列。声纹相似度不是身份概率，也不是自然度验收。
- 后续按录音日期分离训练、验证和测试，排除跨集合的近重复文本。先检验 12GB 显存上的真实训练，再进行未见台词对照试听。

### 已完成的硬件验证

真实 LoRA 试跑完成 2 步，384 个 LoRA 张量在第二步后均发生变化，全部为有限数值，检查点已保存。耗时 58.16 秒（含加载），峰值分配 5.625 GiB、峰值预留 6.373 GiB；torch `2.11.0+cu128`、CUDA 12.8。此检查只证明当前低显存方案能训练，不证明音色质量，试跑权重不作为正式候选。

### 说话状态的复核

用户确认原正式配音与聊天语音是同一人，前者使用正式普通话、后者为随意日常表达。CAM++ 跨两种录音状态的相似度很低，因此不把该分数作为排除日常语音的身份门槛；使用聊天语料内部的稳健离群检查和片段内一致性检查。原正式参考留作后续风格对照。没有把机器分数解释为不同人的证明。

初轮极严格子集仅 35 段、4.61 分钟，尚不足以代表全部自然表达，因此增加 Whisper large-v3 第三路核对和 DNSMOS 噪声质量预测。最终数据以完成后的筛选统计为准，不能把初轮数字当作正式训练规模。

## 复用方案与边界

- 复用 [OpenBMB/VoxCPM](https://github.com/OpenBMB/VoxCPM) 原生 LoRA 训练器，源码固定至 `cce58a5b59303c9bd63d12f23afe6a49a4a80c59`，下载于 2026-10-23，保存在 `E:/VoxCPM-training`。
- 依据[官方训练文档](https://voxcpm.readthedocs.io/en/latest/finetuning/finetune.html)保留真实转写、筛除噪声、保存多个检查点，并与未训练基线比较。机器指标通过不代表最终听感通过。
- 新增独立素材处理与训练启动辅助文件，未修改 `specs.py`、`dub/xiaonian_v10.json`、原有配音脚本或 Backend 类。
- 为 12GB 显存准备小批量、梯度累积、冻结权重 BF16 和激活重计算；是否可用以实际训练结果为准。LoRA 参数与 AudioVAE 保留 FP32，原始模型文件不变。
- 用户指定的中转 `gpt-5.5` 技术复核请求仅含匿名统计与技术方案，返回 HTTP 429（账户限流），本次尚无该模型的有效审查意见；密钥未写入文件，未发送原声和聊天文本。

完整逐段机器标注与排除理由仅保存在本机；本报告只同步匿名进度和验收结果。
