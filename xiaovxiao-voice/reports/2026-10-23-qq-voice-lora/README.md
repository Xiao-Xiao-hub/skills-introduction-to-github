- 使用 CAM++ 做聊天语料内部离群和片段一致性筛查，DNSMOS 做噪声预测；这些是机器指标，不是身份概率或人类音质评分。所有排除原因逐段保存在本机。

- 机器情绪候选：轻快 24、平静 12、低落 5、惊讶 1、未知 1。37 段使用降噪版本，其中 31 段前后情绪分类相同、6 段不同；不同标签不当成确定情绪。另建立 7 段真实情绪参考库，只取训练集且排除降噪前后情绪标签冲突。

## 实际训练与验证

复用 [OpenBMB/VoxCPM](https://github.com/OpenBMB/VoxCPM) 官方 LoRA 训练器，固定源码提交 `cce58a5b59303c9bd63d12f23afe6a49a4a80c59`，本机 `E:/VoxCPM-training`；依据[官方微调文档](https://voxcpm.readthedocs.io/en/latest/finetuning/finetune.html)做小样本实验、保留检查点并用新台词对照，资料查阅于 2026-10-23。采用官方小样本方法不等于本次质量已经合格。

- batch 1、梯度累积 4、rank/alpha 16、学习率 5e-5、24 次优化调用，约 3.1 次数据遍历；前 10 步 warmup，最后学习率归零。
- 冻结主体 BF16、LoRA 和 AudioVAE FP32、激活重计算；实际训练 9,043,968 个 LoRA 参数。原基础模型三份文件哈希均与已固定 A 档案一致。
- 本轮训练耗时 150.89 秒（含加载和验证），峰值分配 6.048 GiB、预留 7.418 GiB。torch `2.11.0+cu128`、CUDA 12.8、算力 `(12, 0)`；未安装 flash-attn。
- 初始到最终检查点 **384/384 个 LoRA 张量发生变化，全部有限数值**。这是权重真实更新的证据，不是自然度证明。此前另有 2 步硬件试跑，未混作本轮训练。
- 最终文件 `voices/human-a-v1/local/qq-corpus-20261023/checkpoints-v1/step_0000024/lora_weights.safetensors`，约 36.22 MB；权重、数据、转写与 TensorBoard 样本只存本机 E 盘。

## 运行问题与边界

- 训练首次加载、随后试听切换模型时各出现一次 Windows `torch_cpu.dll` / `0xc0000005`，发生于权重加载阶段；原错误日志保留。限制 CPU 线程后训练完成；试听改为单线程、进程级 `ATEN_CPU_CAPABILITY=default`、只加载一次基础模型再切换 LoRA，随后生成成功。没有确认底层根因已修复。
- 留出评估第一次遇到 safetensors 不接受 `torch.device` 参数；只在本轮独立辅助文件中把调用参数转为字符串，重跑通过，未改官方源码、原配音脚本或 Backend 类。
- 用户指定中转的匿名技术复核请求两次分别返回 HTTP 429 `All available accounts are currently rate-limited.` 和 `ReadTimeout`；没有取得有效复核意见。未发送原声或聊天文本，未把密钥写入文件，Codex 主路由未更改。
- `specs.py`、`dub/xiaonian_v10.json`、`common.py` 和原配音脚本的哈希均保持原样。全部新增工作由独立本机辅助文件执行。
